# Goji v0.3 GENOME-backed SHADOW Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accumulate genuine, independently verifiable postgame observations in an isolated, durable GENOME SHADOW channel without modifying Goji's canonical predictions, settlement, learning, performance, or model behavior.

**Architecture:** Keep existing v0.3 ECHOSENSE/CARAPACE/evaluator/SCARS/MOLT logic as the only grading implementation; extract a pure decision boundary consumed by both AUDIT and SHADOW. A separately credentialed, narrowly privileged SHADOW client reads frozen verdicts and writes append-only observations to the same Supabase project. Initial GitHub automation is manual and fail-closed; LIVE and schedules stay disabled pending separate release approvals.

**Tech Stack:** Python 3.11, pytest 8, requests 2, GitHub Actions, Supabase/PostgreSQL/PostgREST, existing `goji` package.

**Spec:** `docs/superpowers/specs/2026-09-16-goji-v0.3-shadow-experience-design.md` (approved by Josh 2026-09-16). Also preserve `docs/superpowers/specs/2026-09-16-goji-v0.3-postgame-intelligence.md` and the existing v0.3 plan.

## Global Constraints

- Implement only on `goji-v0.3-postgame-intelligence`, inside Draft PR #4; `main`, production migrations, real GENOME rows, recurring schedules and LIVE remain untouched until their own approvals.
- Initial SHADOW inputs are genuine pregame-frozen TEAM and PLAYER_PROP predictions only; never synthesize/backdate a freeze, supply missing pregame facts using postgame data, or count TEST smoke rows.
- Preserve immutable `shin2_verdicts`, `freeze_fingerprint`, existing `genome_freeze_slate`, `genome_settle`, settlement triggers, official postmortems, hypotheses/evidence, scoreboards, prediction outputs and cold-start labeling.
- AUDIT performs zero GENOME writes; SHADOW may write only scoped, append-only SHADOW observations/revisions; LIVE is unavailable in the initial manual/scheduled workflow. No alternate GENOME architecture.
- Only explicitly verified finality, identity, team/prop mapping, source, timing and evaluator rules produce a proposed grade; missing evidence is UNRESOLVED/REVIEW_REQUIRED.
- Idempotent replays cannot create new sample depth; provider corrections append revisions and disputed versions are excluded from learning.
- SHADOW can retain SCARS diagnoses and MOLT **proposals**, never canonical postmortems, hypotheses/evidence or promotions. Maturity is multidimensional and requires RIVAL, ARENA, FOSSIL and Josh's human approval.
- A production service-role key bypasses RLS: mere client-mode flags and RLS are insufficient isolation. A verified restricted PostgREST identity with only SHADOW RPC permissions is a hard prerequisite. If unavailable, stop prior to automatic deployment rather than using the service key.
- No real-slate validation or experience claim until a genuine completed slate containing team and prop freezes exists and independent ground truth has been checked. Zero eligible rows is reported honestly.
- Use RED → GREEN → whole-suite verification → review → commit for each task. GitHub CI on the **exact final head** is required. Never claim a test, rollback or verification occurred unless tool output confirms it.

## File responsibility map

- `.github/workflows/goji-postgame.yml`: no schedule or LIVE dispatch; separate credential environments for manual AUDIT versus eventual manual SHADOW.
- `scripts/goji_postgame.py`: explicit mode/preflight routing, safe defaults, structured report; no unconditional production-client construction for SHADOW.
- `goji/postgame_evaluation.py` (new): pure shared result validation, deterministic grade and proposed diagnosis; no database imports/writes.
- `goji/postgame.py`: preserve existing AUDIT and LIVE engine behavior while calling the shared evaluator; do not alter trusted settlement RPC semantics.
- `goji/results.py`, `goji/models.py`: preserve provider-reported event start time as an optional normalized evidence field.
- `goji/shadow.py` (new): isolated SHADOW runner that uses the shared evaluator and a restricted client only.
- `goji/shadow_genome.py` (new): small isolated HTTP client for only SHADOW queue, readiness and observation RPCs. No generic `_rpc` that accepts arbitrary function names in its public interface.
- `goji/config.py`: separate `ShadowGenomeConfig`, reading `SUPABASE_URL`, `SUPABASE_SHADOW_JWT` and optional timeout, not `SUPABASE_SERVICE_ROLE_KEY`.
- `supabase/migrations/2026091602_shadow_experience.sql` (new): ordered, restricted append-only observation table and three narrow RPCs, dependent on `2026091601_postgame_intelligence.sql`.
- `tests/test_postgame_cli.py`, `tests/test_shadow_contract.py`, `tests/test_postgame_evaluation.py`, `tests/test_shadow_genome.py`, `tests/test_shadow.py`, `tests/test_shadow_migration.py`: focused RED/GREEN security/compatibility fixtures.
- `README.md`: documented disabled-by-default rollout, credential separation, honest zero-data behavior and migration/release gates.
