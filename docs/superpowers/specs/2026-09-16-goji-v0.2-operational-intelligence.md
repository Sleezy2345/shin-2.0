# Goji v0.2 — Operational Intelligence

## Goal

Make Goji ready for a controlled full-slate run by turning the existing SportsGameOdds, cold-start, and GENOME foundation into a conservative pregame pipeline that validates evidence, treats player props explicitly, separates blocked opportunities from predictions, and freezes a canonical slate without inventing model confidence.

## Non-goals

- Do not claim Goji is trained when it is still cold-start.
- Do not copy market implied probability into model probability.
- Do not bypass CARAPACE to increase pick volume.
- Do not create a second persistence layer or duplicate GENOME.
- Do not merge postgame learning conclusions directly into model behavior from one outcome.

## Architecture

The runnable pregame path is:

`ECHOSENSE -> CARAPACE -> PLASMA-compatible candidate contract -> SPINES-compatible features -> PREYSCAN for PLAYER_PROP -> CORTEX/ColdStartBaseline -> GENOME freeze`

Goji receives normalized event/candidate data with provenance. CARAPACE classifies each opportunity as `PASS`, `PASS_WITH_CAUTION`, or `BLOCKED`. Player props also pass through PREYSCAN. Only passing opportunities may become predictions. Blocked opportunities are recorded separately and never counted as predictions.

The existing `ColdStartBaseline` remains deliberately conservative. It may preserve a supplied illustrative baseline probability when present, but every v0.2 decision remains `COLD_START` and `NO_ROAR` until later model work earns a different status.

## Candidate contract

A pregame candidate carries:

- `prediction_id`
- `sport`
- `game_id`
- `prediction_type`
- `selection`
- `market_key`
- `independent_group_key`
- `inputs`
- `features`
- nonempty `provenance`
- `context`

`PLAYER_PROP` inputs additionally require:

- `player`
- `market`
- numeric `line`
- `side`
- `expected_participation=True`

Role/opportunity and matchup context are evidence-quality fields. Missing them does not manufacture certainty; PREYSCAN marks the candidate `PASS_WITH_CAUTION` so the frozen CARAPACE state preserves the limitation.

## CARAPACE rules

CARAPACE blocks when any canonical identity/evidence field is missing, provenance is empty, evidence is older than the hard freshness limit, evidence timestamps are in the future beyond clock tolerance, or `context.conflict_level` is `CRITICAL`.

CARAPACE returns `PASS_WITH_CAUTION` when evidence is older than the caution threshold or `context.conflict_level` is `MEANINGFUL`.

Default freshness policy for the operational runner:

- caution after 30 minutes
- block after 90 minutes
- permit up to 5 minutes of positive clock skew

These defaults are parameters, not hidden constants in callers, so later sport/source-specific policies can replace them without changing the validation contract.

## PREYSCAN rules

PREYSCAN only applies to `PLAYER_PROP` candidates.

Block when player, market, numeric line, side, or confirmed participation is missing/invalid. `expected_participation=False` or unknown/missing participation is blocked.

Mark `PASS_WITH_CAUTION` when role/opportunity evidence or matchup context is absent. This preserves safety without pretending that a thin prop profile is equivalent to a fully contextualized one.

## GENOME freeze payload

Every passing prediction is converted to the live `genome_freeze_slate` shape:

```json
{
  "prediction_id": "...",
  "payload": {
    "sport": "MLB",
    "game_id": "...",
    "prediction_type": "TEAM" | "PLAYER_PROP",
    "selection": "...",
    "market_key": "...",
    "independent_group_key": "...",
    "roar_action": "ROAR" | "NO_ROAR",
    "model_status": "...",
    "model_probability": null,
    "market_implied_probability": null,
    "reason": "...",
    "inputs": {},
    "features": {},
    "provenance": [],
    "carapace_state": {"decision": "PASS" | "PASS_WITH_CAUTION", "reasons": []},
    "context": {}
  }
}
```

The Supabase function adds the batch `slate_id` and `capture_mode=FULL_SLATE` during freeze. The Python runner must not invent a conflicting slate id.

Blocked payloads contain `blocked_id`, `sport`, `game_id`, `prediction_type`, `market_key`, `reason`, `carapace_state.decision=BLOCKED`, provenance, and context.

## Operational runner

`OperationalPregame` prepares a complete slate in memory, preserving both predictions and blocked opportunities. It exposes a separate `freeze()` step so preparation can be inspected/tested without writing GENOME. Freeze calls the existing `GenomeClient.freeze_slate()` exactly once with both collections.

The runner must be deterministic for the same candidates, timestamps, and freshness policy so retrying a slate does not create a different payload accidentally.

## Tomorrow-readiness criteria

Before v0.2 can merge:

1. Existing v0.1 tests remain green.
2. CARAPACE good/stale/conflict/missing-evidence cases are covered.
3. PREYSCAN valid/missing-field/participation/thin-context cases are covered.
4. Operational slate preparation produces canonical prediction and blocked payloads.
5. PLAYER_PROP payloads satisfy the live GENOME required fields.
6. Market implied probability remains separate from model probability.
7. GENOME freeze is one explicit write after preparation; preparation itself is read/write-free.
8. CI is green on Python 3.11 before merge.

## Postgame follow-on

Settlement -> SCARS diagnosis -> expectation error -> MOLT candidate lesson -> Evidence Maturity remains the next stage. v0.2 must preserve all context needed for that loop, but it does not auto-promote lessons or alter model behavior based on single outcomes.
